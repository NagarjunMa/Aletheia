PHASE 34 — Prompt Leak Fix: Preamble + Suffix Strip
Status: [x] COMPLETE — 2026-06-03 (branch fix/prompt-leak-preamble-suffix)
--------------------------------------------------------------------------------
Triggered by live leak: connection note shipped with "Counting carefully
before finalizing." preamble + "---" separator + "Character count: 221 ✓"
suffix. Root cause: prompt verb "COUNT your characters before returning"
read as reasoning step; weak OUTPUT gate; no post-process strip.

FILES MODIFIED:
  [x] lib/ai/sanitizer.ts — new stripModelPreambleAndSuffix() exported.
      Walks lines from both ends, drops meta lines matching narrow regex
      (preambles, label headers, char/word-count tails, separators).
      Also strips inline label prefix on first remaining line.
  [x] lib/ai/prompts/linkedin-connection.ts —
        PROMPT_VERSION 1.0.0 → 1.1.0
        COUNT line → "Stay silently under 270 chars... Do not narrate or
        annotate this trimming."
        OUTPUT FORMAT block tightened: "Return ONLY the connection note
        body. Nothing else. Do NOT include: preambles, separator lines,
        character/word counts, labels, quotes, explanations..."
        cold_email + linkedin_inmail OUTPUT FORMAT also tightened:
        "First character must be '{'. Last character must be '}'."
  [x] app/api/extension/generate/route.ts — stripModelPreambleAndSuffix
      wired in before sanitize() at 3 sites:
        - rawContent (linkedin_connection)
        - parsed.subject_line (cold_email / linkedin_inmail)
        - parsed.body         (cold_email / linkedin_inmail)

TESTS ADDED (10 new):
  [x] lib/ai/sanitizer.test.ts — stripModelPreambleAndSuffix corpus:
        - real-world leak (Counting + --- + Character count)
        - "Here is the message:" leading label
        - "Output:" inline label prefix
        - "Word count: N ✓" trailing tail
        - separator styles (---, ***, ===, ___)
        - "Let me draft this." preamble
        - false-positive resist: "Here is what I do for fun..." (kept)
        - false-positive resist: "Quick note on your final project..." (kept)
        - empty input
        - all-meta input → empty string

DEFENSE-IN-DEPTH: prompt fix lowers leak rate; sanitizer catches drift.

KNOWN LOCAL-LOAD GOTCHA (logged for later cleanup, not blocking)
--------------------------------------------------------------------------------
public/ascendia-extension.zip is currently BROKEN — esbuild bundles
service-worker.js but leaves importScripts('auth.js') intact while
auth.js is not an entry point, so the unzipped folder has no auth.js
and Chrome rejects with "Service worker registration failed. Status
code: 15".

WORKAROUND for local dev: load ascendia-extension/ source directly
into Chrome — files are already plain MV3 JS, no bundling needed.

PROPER FIX before Chrome Web Store submission: update
scripts/build-extension-zip.mjs to either (a) add background/auth.js
as an entry point AND strip importScripts() from service-worker, OR
(b) skip bundling for background/* and copy verbatim into the zip.
